# Launch Checklist

## Positioning

- Confirm the primary description: "HyperPulse is a read-only, Hyperliquid-native intelligence workspace for active perp traders."
- Confirm public demo surfaces: Home, Markets, Portfolio, Docs.
- Keep the accelerator pitch limited to the public demo and read-only intelligence workflow.
- Avoid language that implies custody, execution, wallet control, or financial advice.

## Trust And Safety Copy

- State that HyperPulse does not ask for private keys.
- State that HyperPulse does not ask for seed phrases.
- State that HyperPulse does not take custody.
- State that portfolio lookup uses public wallet addresses only.
- State that reaction levels are market context, not trade instructions.

## Demo Flow

- Homepage loads and explains the product clearly.
- Markets table is easy to reach from the homepage.
- Markets table supports opening an asset drawer.
- Asset drawer includes reaction levels and concise asset context.
- Portfolio flow accepts a public wallet address.
- Portfolio view shows positions and performance.
- Journal flow is visible as part of portfolio review.
- Docs page explains trust, read-only data, and product limitations.

## Application Package

- Reusable company description is concise and consistent.
- Problem, solution, user, why now, traction, defensibility, and business model answers are ready.
- Alliance answer is tailored to crypto-native application infrastructure.
- a16z CSX answer is tailored to crypto startup scale and market timing.
- Outlier answer is tailored to early positioning and fundraising readiness.
- Beacon answer is tailored to on-chain user value and ecosystem maturity.
- YC answer is simple, direct, and founder-friendly.

## Beta Readiness

- Define the target beta user.
- Prepare the public demo funnel.
- Prepare live walkthrough script.
- Prepare feedback questions.
- Track public wallet paste rate and trust objections.
- Track repeat tester conversion.

## Final Pre-Submission Review

- Read every accelerator answer out loud for clarity.
- Verify every claim can be supported by the current demo or near-term beta plan.
- Cut jargon that does not help the investor or accelerator reviewer.
- Ensure all materials repeat the same trust posture: no private keys, no seed phrase, no custody.
- Keep the pitch focused on Hyperliquid-native intelligence for active perp traders.
