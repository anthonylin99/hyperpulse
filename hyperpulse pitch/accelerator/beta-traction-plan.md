# Beta Traction Plan

## Objective

Prove that active Hyperliquid perp traders understand the value of HyperPulse, trust the read-only model, and want to return to the product as a daily intelligence workspace.

## Target Beta User

The first beta user is an active Hyperliquid trader who:

- Trades or monitors perpetual futures regularly.
- Wants faster market scanning and asset context.
- Reviews open positions and performance.
- Is willing to paste a public wallet address for read-only analysis.
- Cares about trust, privacy, and avoiding custody risk.

## Beta Promise

"Use HyperPulse to scan Hyperliquid markets, inspect asset context, review a public wallet portfolio, and improve your trading review process without private keys, seed phrases, approvals, or custody."

## Public Demo Funnel

1. Homepage
   - Explain what HyperPulse is and who it is for.
   - Make the read-only trust model visible immediately.

2. Markets Table
   - Let users scan active Hyperliquid markets.
   - Drive them into an asset drawer for more context.

3. Asset Drawer And Reaction Levels
   - Show asset-level context and reaction levels.
   - Keep the language focused on decision support, not trade calls.

4. Public Wallet Portfolio
   - Ask users to paste a public wallet address only.
   - Explain that HyperPulse does not need private keys, seed phrases, approvals, or custody.

5. Positions, Performance, And Journal
   - Let users review current positions and performance.
   - Encourage users to capture trade notes and post-trade reflections.

6. Docs And Trust
   - Give users a clear explanation of the read-only model.
   - Address permission, privacy, and custody concerns before they become blockers.

## Beta Milestones

- Recruit 25 target beta users from Hyperliquid-focused communities and founder networks.
- Complete 10 live product walkthroughs using the core demo flow.
- Collect 15 structured feedback forms focused on clarity, trust, and repeat-use intent.
- Identify the top 3 reasons users would return daily.
- Identify the top 3 trust or comprehension blockers.
- Convert 5 users into weekly repeat testers.

## Feedback Questions

- Did you understand that HyperPulse is read-only?
- Did anything make you think HyperPulse needed custody or wallet control?
- Which screen felt most useful: Markets, asset drawer, Portfolio, performance, journal, or Docs?
- Would you paste a public wallet address into this product?
- What would make this useful enough to open daily?
- What would make you pay for a professional version?

## Metrics To Track

- Homepage-to-Markets click-through.
- Markets-to-asset-drawer engagement.
- Public wallet paste rate.
- Portfolio review completion.
- Journal interaction rate.
- Docs and trust page visits.
- Beta user return rate.
- Qualitative trust objections.

## Accelerator Traction Narrative

The traction story should stay simple: HyperPulse is validating a focused workflow with active Hyperliquid perp traders. The current beta measures whether users move from market scanning to read-only portfolio review, whether the trust model is clear, and whether the product earns repeat usage as a daily intelligence workspace.
